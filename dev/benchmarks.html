Where PATHPACK.jl Does Not Win ​

  • Few sources. On one query of 145 sources, NetworKit is faster than PATHPACK.jl. Single-source methods do work per source, and with few sources there is little to share; PATHPACK.jl pays for a factorization of the whole graph.

  • Unweighted grids. On an unweighted warehouse grid PATHPACK.jl is only 1.15× faster than graph-tool and NetworKit.

  • One mesh on the GPU. ROME is faster on one of our graphs, a biplane mesh, by 1.12×.

How We Measure ​

Each time is the wall-clock time from the graph in memory to the full answer in memory: for all pairs, every distance of the   result. Loading files and writing results are not counted, for any code. The answers of every code are checked against each other. Every other code runs with the best settings we found for it. CPU comparisons use the same cores for every multithreaded code; single-threaded codes are marked as such.

The benchmark scripts and raw measurements are public in the PATHPACK.jl repository.
