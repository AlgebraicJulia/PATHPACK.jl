Exact Diffusion for Graph Neural Networks ​

Download notebookThe same code as on this page, ready to run in Jupyter with IJulia.

Graph diffusion convolution (GDC) rewires a graph before a graph neural network sees it. Each node gets new neighbours: the nodes that a random walk from it visits most. The most common diffusion is personalized PageRank (PPR). PyTorch Geometric implements it as the GDC transform, and its exact mode inverts a dense   matrix. PATHPACK.jl computes the same matrix as a sum over walks, with a sparse factorization.

119×faster than PyTorch's dense inverse on a 47,004-node mesh, 16 CPU threads, float64
22.6×faster on PubMed (19,717 nodes): 1.93 s instead of 43.7 s
69×faster on one NVIDIA B200 for the same mesh: 124.5 ms instead of 8.64 s

A Small Graph With Communities ​

Citation graphs have communities: papers mostly cite papers in their own field. A random graph with four communities of 150 nodes stands in for one here. Two nodes in the same community are linked with probability 3%; two nodes in different communities with probability 0.2%.

julia
using PATHPACK, SparseArrays, LinearAlgebra, Random
using PATHPACK.CPU: PlusProd, mstar

Random.seed!(3)
n = 600
community = rand(1:4, n)
src = Int[]; dst = Int[]
for i in 1:n, j in (i + 1):n
    p = community[i] == community[j] ? 0.03 : 0.002
    if rand() < p
        push!(src, i, j); push!(dst, j, i)
    end
end
A = sparse(src, dst, 1.0, n, n)
nnz(A) ÷ 2    # the number of edges
1623

The Diffusion Matrix ​

Build and exactly as GDC does, with  , and take the star.

julia
α = 0.15
Â = A + sparse(1.0I, n, n)                      # add self-loops
d = vec(sum(Â; dims = 2))                       # degrees
T = Diagonal(1 ./ sqrt.(d)) * Â * Diagonal(1 ./ sqrt.(d))
B = (1 - α) .* T

S = α .* mstar(PlusProd(), B);

A dense inverse gives the same matrix, up to rounding. This is what PyTorch Geometric's exact mode computes, with torch.inverse.

julia
S_dense = α .* inv(Matrix(I - B))
maximum(abs.(S - S_dense)) / maximum(abs.(S_dense))
3.33066907387547e-16

Since is symmetric, so is . Its entries are sums of products of nonnegative numbers, so none is negative; an entry is zero exactly when no walk joins the two nodes.

julia

Sparsifying, as GDC Does ​

GDC keeps only the strongest entries of , so the new graph stays sparse. With top- sparsification it keeps the largest entries of each column, and then normalizes each column to sum to one (normalization_out = "col"). The result is a weighted graph with incoming edges per node.

julia
k = 16
rows = Int[]; cols = Int[]; vals = Float64[]
for j in 1:n
    top = partialsortperm(view(S, :, j), 1:k; rev = true)
    w = S[top, j]
    append!(rows, top); append!(cols, fill(j, k))
    append!(vals, w ./ sum(w))
end
S_k = sparse(rows, cols, vals, n, n)
nnz(S_k), all(sum(S_k; dims = 1) .≈ 1)
(9600, true)

The new neighbours are the nodes the walks visit most, so most of them share the node's community:

julia
same = count(community[rows] .== community[cols]) / length(rows)
0.7939583333333333

Into a PyTorch Geometric Pipeline ​

A PyG graph stores its edges as edge_index (two rows: source and target, from 0) and their weights as edge_attr. The arrays rows, cols and vals above are exactly these, up to the shift to 0-based indices. One way to hand them over is a raw binary file:

julia
write("gdc_edges.bin", Int64.([rows cols] .- 1))   # sources, then targets
write("gdc_weights.bin", Float32.(vals))

and in Python:

python
import numpy as np, torch

edges = np.fromfile("gdc_edges.bin", dtype=np.int64).reshape(2, -1)
weights = np.fromfile("gdc_weights.bin", dtype=np.float32)
data.edge_index = torch.from_numpy(edges)
data.edge_attr = torch.from_numpy(weights)

This replaces T.GDC(..., exact=True) in the preprocessing. The model and the training loop do not change.

On a GPU, the CUDA extension computes the same star with plus-times in Float64. is symmetric, which the GPU solver needs:

julia
using CUDA
using PATHPACK.GPU: apsp_gpu

S = α .* apsp_gpu(B; semiring = PlusProd())    # a CuMatrix{Float64}

The gap grows with the graph. A dense inverse costs operations whatever the graph. The sparse factorization costs much less on sparse graphs, and meshes, with their small separators, are where it gains most. On PubMed, PyTorch Geometric's whole exact GDC transform takes 108.7 s on the same CPU node.

Exact mode only

These numbers compare exact diffusion with exact diffusion. PyTorch Geometric's exact mode is the dense one, and its memory grows as , so on large graphs most users run GDC in its approximate mode (exact=False), which estimates each PPR vector with a local push algorithm. The table does not compare against that mode. PATHPACK.jl gives the exact matrix, and its output is still numbers.
