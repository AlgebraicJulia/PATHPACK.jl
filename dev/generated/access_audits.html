Access Audits: Who Can Reach What ​

Download notebookThe same code as on this page, ready to run in Jupyter with IJulia.

A security audit asks a simple question about a system's permissions: who can actually reach what? The permission on one file is easy to read. Access is a property of whole routes. On a Linux file system, a user can open a file only if they are allowed through every directory on the way to it, and a second route to the same file, through a shared folder or a mount, can let in people its owner never meant to. The question is about every user and every file at once: an all-pairs problem.

In the semiring OrAnd, the weight of an arc is a set of users, stored as the bits of an integer. Along a path the sets are intersected (  , bitwise and): a user gets through only if every step lets them through. Over all paths they are united (  , bitwise or): one open route is enough. The star G holds, for every pair i, j, the set of users who can get from i to j.

A teaching model

The model below follows the rules that matter most for audits: to look up a name in a directory you need execute permission (x) on that directory, and to read a file you need read permission (r) on it. It leaves out access control lists, the sticky bit, listing directories (r on a directory) and root, who bypasses permissions. Symbolic links add no routes, since the kernel checks the target's own path; bind mounts and hard links do, and the example uses a bind mount.

A File System as a Graph ​

Five accounts, and the groups they belong to.

who(bits) = [u for u in users if bits & bit(u) != 0]

Then an administrator makes Alice's dataset available to the lab with a bind mount, the equivalent of mount --bind /home/alice/datasets /srv/shared/datasets. The mount point is a second name for the same directory.

julia
mounts = ["/srv/shared/datasets" => "/home/alice/datasets"]
1-element Vector{Pair{String, String}}:
 "/srv/shared/datasets" => "/home/alice/datasets"

Each directory and file is a vertex, and each name in a directory is an arc from the directory to it. The arc's label is the set of users allowed to look the name up: those with execute permission on the directory. Whether a user has a permission depends on which class they fall in, owner, group or other, exactly as the kernel decides.

julia
function allowed(entry, perm)                      # perm: 4 read, 1 execute
    _, owner, group, mode = entry
    bits = UInt32(0)
    for u in users
        shift = u == owner ? 6 : u in members[group] ? 3 : 0
        (mode >> shift) & perm != 0 && (bits |= bit(u))
    end
    return bits
end

function filesystem(fs, mounts)
    id = Dict(e[1] => k for (k, e) in enumerate(fs))
    src = Int[]; dst = Int[]; label = UInt32[]
    for (path, _...) in fs
        path == "/" && continue
        p = dirname(path)
        push!(src, id[p]); push!(dst, id[path]); push!(label, allowed(fs[id[p]], 1))
    end
    for (point, target) in mounts                  # the mount point's directory leads to the mounted directory
        p = dirname(point)
        push!(src, id[p]); push!(dst, id[target]); push!(label, allowed(fs[id[p]], 1))
    end
    n = length(fs)
    return sparse(src, dst, label, n, n, |), id
end

A, id = filesystem(fs, mounts)
size(A, 1), nnz(A)    # entries, and names in directories (the mount adds one)

Every Route at Once ​

One call computes the star: for every pair of entries, the users who can get from one to the other.

julia
G = mstar(OrAnd(), A);

A user can read a file when they can reach it from / and have read permission on it.

julia
readers(path; from = "/") = who(G[id[from], id[path]] & allowed(fs[id[path]], 4))

Fixing It ​

Two fixes close the leak: remove the mount, or make the dataset private where it lives. Take the second, since the lab may need the mount for other files, and audit again.

julia
fixed = [e[1] == "/home/alice/datasets" ? (e[1], e[2], e[3], 0o700) : e for e in fs]
A2, _ = filesystem(fixed, mounts)
G2 = mstar(OrAnd(), A2)
who(G2[id["/"], id["/home/alice/datasets/patients.csv"]] & allowed(fixed[id["/home/alice/datasets/patients.csv"]], 4))
1-element Vector{String}:
 "alice"

Only Alice now. Every other answer is unchanged:

julia
others = setdiff(1:length(fs), [id["/home/alice/datasets"], id["/home/alice/datasets/patients.csv"]])
G2[others, others] == G[others, others]
true

From Anywhere, Not Only From the Root ​

Every row of the star is a starting point. A process that is already inside a directory, its working directory, looks names up from there, so what it can reach depends on where it starts. The web server runs in /var/www:

julia
[path for (path, _...) in fs if G[id["/var/www"], id[path]] & bit("www") != 0]
2-element Vector{String}:
 "/var/www"
 "/var/www/config.php"

The full matrix holds this for every directory and every user at once: which users can get from any directory to any other.

Checking the Answer ​

Each user can be checked on their own: user u can get from i to j exactly when j is reachable from i through the arcs whose labels contain u. Plain reachability, here as finite shortest-path distances, one computation per user:

julia
all(users) do u
    I, J, L = findnz(A)
    keep = (L .& bit(u)) .!= 0
    Du = mstar(MinPlus(), sparse(I[keep], J[keep], ones(count(keep)), size(A)...))
    ((G .& bit(u)) .!= 0) == isfinite.(Du)
end
true

One OrAnd star answers for all users at once.

Larger Systems ​

A real file system has millions of entries, and all pairs would not fit in memory. An audit rarely needs them all: it needs the rows of the places users start from, such as /, each home directory, and the working directories of services. Factorize once and solve for those rows (see Factorize Once, Query Many Times):

julia
F = mlu(OrAnd(), A)
B = fill(UInt32(0), 1, size(A, 1)); B[id["/"]] = typemax(UInt32)
rmul!(B, F)
vec(B) == G[id["/"], :]
true

A label is a bit, so UInt32 holds 32 users and UInt64 64. For more, give the bits to groups instead of users, or compute one star per block of 64 users.

The Same Pattern Elsewhere ​

The model, permissions on the steps and access along whole routes, is the one behind several kinds of security analysis:

  • Directory services. In Active Directory, users, groups and computers form a graph whose arcs mean "can log in to" or "can change the password of"; attack-path tools such as BloodHound ask which accounts can reach the domain administrators.

  • Cloud permissions. Identities that can assume roles that can assume other roles: which of them can reach a sensitive storage bucket?

  • Networks. Which hosts can reach which services through the firewall rules between subnets?

Other semirings ask other questions of the same graph. With a cost on each step, MinPlus gives the cheapest route in; with the probability that each step succeeds, MaxProd gives the most likely chain. The use is defensive: to find the routes no one intended, and close them.
